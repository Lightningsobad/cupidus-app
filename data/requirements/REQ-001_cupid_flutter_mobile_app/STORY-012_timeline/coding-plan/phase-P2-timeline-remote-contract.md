## 3. Tasks

- Implement `TimelineEventDto.fromJson`: required `id` (String) and `title` (String); optional `description`, `photoUrl`, `icon`; `createdAt` parsed from an ISO string; `type` parsed from `memory | milestone | system` with an unknown/absent value falling back to `memory`. Throw a typed decode error (not a raw cast error) when `id` or `title` is missing or not a String.
- Implement `TimelineEntry` (immutable, value equality) with `isAutoGenerated => type != TimelineEventType.memory`. The domain model carries the memory's date as `createdAt` — the server has no separate date column, `date` on create simply overwrites `createdAt`.
- Implement `TimelineDraft` (title, date, description) with `toJson()` emitting `title`, optional `description`, `date` as an ISO-8601 string, `type: 'memory'`, and a Material-Symbols `icon` name (default `favorite`). Do not send `photoUrl` — photo attachment is deferred (D-012-7).
- Implement `TimelineRemoteDataSource` taking `CupidApi`: `fetchFirstPage()` issues `GET /timeline` with `limit=50`, `offset=0` and decodes `response.data` as a `List`; `createEntry(TimelineDraft)` issues `POST /timeline`. Use the shared `Dio` from `CupidApi` because the generated ops are typed `Response<void>` and discard the body. Do not construct `Dio`, do not import `package:cupid_api/...` directly, and do not switch on `DioExceptionType` — rethrow the `CupidApiFailure` from `DioException.error`.
- Guard the list decode: a non-list body or a single undecodable element must produce a typed failure rather than a partially built list.

## 4. Acceptance Criteria

- A representative `GET /timeline` payload decodes into `TimelineEntry` values with correct newest-first order preserved from the server.
- Absent and explicit-null `description`, `photoUrl`, and `icon` all decode without error.
- An unknown `type` string decodes as `memory` rather than throwing.
- A missing or non-String `id`/`title` produces a typed decode failure.
- `createEntry` sends exactly the fields listed above and no others.
- Connection failures surface as `NetworkUnavailableFailure` / `TimeoutFailure`, and a 404 surfaces as `HttpStatusFailure(404, ...)`.
- No backend file is modified.
- `flutter analyze` is clean.
