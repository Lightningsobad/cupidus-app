## 3. Tasks

- Build `TimelineScreen` with the shared header (back chevron, localized title) and a scroll body driven by `BlocBuilder<TimelineCubit, TimelineState>`.
- Render the vertical connector line and per-entry dot markers positioned from the horizontal margin token, not hardcoded pixels (UX §3), so the line stays aligned with the dots across widths.
- Build `TimelineEntryCard`: leading icon, title, trailing date, optional body copy, optional photo slot. Title and body must use `colorText` / `colorTextMuted`; accent tokens are for icons and dots only (UX §4). Render the date at ≥11pt per the UX §4 deviation note rather than the source's 9.5px.
- Show the "auto-added" pill when `entry.isAutoGenerated`, and offer no delete affordance on those entries (the backend rejects deleting `milestone` entries). Entries of every `type` must render — server-generated milestones already arrive in this feed.
- Map the entry `icon` string to a Material Symbols glyph when it is a known symbol name; when it is not (the backend default is an emoji), render it as a text glyph instead of failing.
- Render the photo with an error/placeholder fallback so an unreachable `photoUrl` degrades gracefully instead of throwing; do not add an image-caching package.
- Build `TimelineSkeleton` with exactly 5 placeholder cards matching real card dimensions (UX §2 `hint-placeholder-count="5"`), shown for `loading`.
- Render `empty`, `offlineNoCache`, and `error` surfaces with their localized copy and a retry action; render the offline banner above the list for `ready(isOffline: true)`.
- Place the dashed "Add a memory" affordance at the bottom of the list using the design-system add-action component. Wiring it to the sheet is P6; in this phase it may be present and inert.
- Add semantics labels for icon-only affordances, and expose the offline banner and auto-added pill text to screen readers (UX §4).
- Do not add a milestone/progress banner — out of scope per architecture D-012-9.
- Append the configuration-guide note described in 1B.

## 4. Acceptance Criteria

- Each `TimelineState` renders its intended surface, asserted by widget tests.
- `loading` renders exactly 5 skeleton cards.
- `ready(isOffline: true)` renders both the cached entries and the offline banner.
- `offlineNoCache` renders the "can't load yet" surface, never the "no memories yet" copy.
- An auto-generated entry renders the pill and exposes no delete affordance.
- An unreachable `photoUrl` renders the placeholder without throwing.
- Icon-only affordances expose accessible labels.
- The configuration-guide note is present.
- `flutter analyze` is clean.
