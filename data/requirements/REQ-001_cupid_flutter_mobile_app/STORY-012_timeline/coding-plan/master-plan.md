## 6. Risks And Notes

- Risks:
  - Drift + `build_runner` codegen is new to this repository; P1 must commit the generated `app_database.g.dart` and record the exact generate command so later stories inherit a working generator.
  - `sqlite3_flutter_libs` is the first native dependency added since bootstrap; the P8 `flutter build apk --debug` gate is the real proof it did not break the Android build.
  - `mobile/lib/features/home/presentation/home_screen.dart`, `mobile/lib/core/di/service_locator.dart`, and both `.arb` files are also edited by sibling epic-4 stories in this wave. Keep every edit additive and in a single contiguous block; keep the entry-card widget in `features/timeline/`, not inline in `home_screen.dart`.
  - Removing or renaming `Key('home_screen_ready_signal')` in P7 would break the requirement-wide runtime readiness signal declared in the runtime registry.
- OQ-driven constraints:
  - ADR-007 / OQ4: Drift is a read-through, server-authoritative cache. No offline write queue, no outbox, no optimistic insert, no client-generated ids, no automatic retry.
  - A1: no backend change of any kind, including OpenAPI response-schema decorators.
  - R3 (libsodium): resolved as **not required** for STORY-012 in `../architecture/solution.md` §1. Do not add libsodium, FFI, or an encrypted Drift cipher in any phase.
- Migration / rollout notes: no server migration. Drift schema v1 is disposable cache; a future bump may drop and recreate rather than migrate.
- Notes:
  - Deferred by architecture decision and therefore **not** phase scope: photo attachment on create (D-012-7), pagination beyond the first 50 entries (D-012-8), the milestone/progress banner (D-012-9), delete-entry UI, and offline photo caching. Photo **display** of an existing `photoUrl` stays in P5.
  - Server-generated `type: milestone` entries already arrive in the same `GET /timeline` feed (pet-milestone listener). P5 renders them read-only with the UX "auto-added" pill and offers no delete affordance.
