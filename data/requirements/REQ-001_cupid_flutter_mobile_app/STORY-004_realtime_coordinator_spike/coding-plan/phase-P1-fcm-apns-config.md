## 3. Tasks

- Add `UIBackgroundModes` with `remote-notification` to `mobile/ios/Runner/Info.plist`. Do **not** add the Critical Alerts entitlement (D1/ADR-002).
- Declare an Android default notification channel (metadata entry referencing the channel id) in `AndroidManifest.xml` and record the exact channel id in the configuration guide so P3 uses the same value.
- Document in `../../deployment/configuration-guide.md`, in a new FCM/APNs section:
  - how to generate and upload the APNs auth key to the Firebase project, and that it is a manually supplied secret never generated by an agent;
  - the Android channel id and its purpose;
  - the FCM HTTP v1 injection procedure used to exercise the background leg with the existing `backend/service-account.json` credential, including a sample payload in the exact ADR-012f shape with `priority: high` (Android) and `content-available: 1` / `apns-priority: 5` (iOS);
  - an explicit note that this injection path exists only because the backend has no dispatch (R9) and must be replaced by server-side `admin.messaging()` before background reminders ship.
- Confirm and record that no new environment variable or `--dart-define` key is required.

## 4. Acceptance Criteria

- iOS declares the remote-notification background mode; the Critical Alerts entitlement is absent.
- Android declares a default notification channel whose id is recorded in the configuration guide.
- The configuration guide FCM/APNs section is sufficient for another operator to upload the APNs key and inject a test push without reading this plan.
- No new env var or `--dart-define` key is introduced.
