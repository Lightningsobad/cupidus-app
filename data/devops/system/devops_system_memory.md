## 3. Development-Local Policy

- Current machine expectation: a single developer machine running several generated projects concurrently. Multi-project safety is now provided by the shared `devstack` stack (`~/.devstack`) rather than per-repo Compose naming/port-scanning: every project gets its own Postgres database+role, Redis logical db, and a sticky block of reserved application ports in `21000-21999`. See `.claude/skills/devops/references/shared-local-infrastructure.md`.
- Deploy entrypoint: `scripts/start-dev.sh`, live-verified against the shared stack.
- Required local dependencies or services: shared devstack Postgres 16 + Redis 7 (this project's private tenant, provisioned by `devstack use`; no repo-local Postgres/Redis container), Node 20/22 (backend build/run; verified against host Node 20.20.2), Flutter SDK + Android/iOS toolchains (mobile, `mobile/` scaffold present), `devstack` CLI on PATH.
- Shared-infra adoption (2026-08-20, STORY-059): `backend/docker-compose.yml`'s `postgres`/`redis` services were retired behind a `profiles: ["legacy"]` guard by `devstack adopt --apply` (backup at `backend/docker-compose.yml.devstack-backup.1787195883`); the prior local containers (`cupid-apps-postgres-1`/`cupid-apps-redis-1`) were stopped, not removed. Postgres data was dumped and restored into the shared tenant database `cupid_apps` (backup: `~/.devstack/backups/cupid-apps/cupid.20260820T031803Z.sql`); the restored tables came back owned by the shared admin role and had to be reassigned to the `cupid_apps` tenant role (`ALTER TABLE ... OWNER TO cupid_apps` per table) before the app could read its own data — see `data/devops/system/runtime-command-registry.json` `sharedInfra.legacyCompose.dataMigration` for the exact detail. Redis data was NOT migrated (devstack has no automatic Redis migration path); if old cache/session state is needed, it must be copied manually from the stopped `cupid-apps-redis-1` container before it is ever removed. The `backend`/`nginx` services in the same Compose file are untouched — they build the VPS/production image (`api-cupid.tikup.me`) and are a separate, direct-instruction-only concern (see §4).
- Dependency host port policy: Postgres/Redis are reached at whatever loopback host/port `devstack use` assigns this project's tenant (verified live this pass: Postgres `127.0.0.1:25000`, Redis `127.0.0.1:25001`) — never a repo-scanned or hardcoded port. The backend's own port comes from its `api` role reservation (`devstack port claim`, current value `21020`, read from `DEVSTACK_PORT_API`/`PORT`/`API_PORT`), not a scanned free port. `docs`, `mobile-metro`, and `ws` roles were also auto-reserved by `devstack adopt`'s directory-presence heuristic but are not wired into any script — see `sharedInfra.reservedPortsNote` in the runtime registry for why (no docs dev server, Flutter has no Metro bundler, websockets share the `api` port).
- Project-local env contract path: `.env.devstack` (generated, gitignored, regenerated by `devstack use`/`scripts/setup.sh`; do not hand-edit) merged into repo-root `.env` (also gitignored). Holds `POSTGRES_HOST`/`PORT`/`USER`/`PASSWORD`/`DB`, `DATABASE_URL`, `TEST_DATABASE_URL`, `REDIS_HOST`/`PORT`/`DB`/`PREFIX`/`URL`, and `DEVSTACK_PORT_*`/role-alias port keys. `scripts/lib/common.sh` `require_devstack_env()` sources `.env.devstack` into the running shell; the old `env_get`/`env_set`/Compose-port-scanning helpers were removed since there is no longer a repo-local free port to resolve.
- Smoke or verification expectation: `backend-api` readiness is a live Swagger/JSON probe (`GET /api-docs-json` returns 200) — re-verified live against a real `npm run start:dev` process on the shared-devstack tenant after the ownership fix above; `mobile-app` readiness is `flutter test` exercising the `Key('home_screen_ready_signal')` widget test — verified live (1317/1317 pass), not a live backend dependency.
- Common recovery or rerun notes: `scripts/setup.sh` verified idempotent post-migration (`devstack use --check` exits 0 with empty `envDrift` both before and after a rerun; no duplicate managed-block lines reappear in `.env`). `devstack doctor` still flags several stopped/duplicate Postgres/Redis containers belonging to OTHER local projects on this machine (`reverse-tiktok`, `ai-automation-testing`, `tikops`, `travala-cs`, `automation-*`, a `local-postgres-1`/`local-redis-1` pair) — none of those are owned by `cupid-apps` and are out of this story's scope; they are only visible because `devstack doctor` scans the whole machine.
