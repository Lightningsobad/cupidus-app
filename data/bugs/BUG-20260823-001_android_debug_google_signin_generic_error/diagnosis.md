## Instrumented Reproduction

`_guard` in `mobile/lib/features/auth/data/firebase_auth_sign_in_gateway.dart`
converts every provider exception into `UnexpectedAuthFailure` and logs
nothing, so the on-device failure carried zero diagnostics. Temporary `print`
instrumentation was added to each `catch` branch, the debug APK rebuilt and
reinstalled, and the tap repeated. Logcat then produced the root-cause line:

```
08-23 20:49:35.499  4998  4998 I flutter : BUGPROBE GoogleSignInException code=GoogleSignInExceptionCode.clientConfigurationError desc=serverClientId must be provided on Android details=null
```

The instrumentation was fully reverted afterwards (`git diff` on the gateway is
empty); it is **not** part of the fix.

## Root Cause

`google_sign_in` 7.x on Android routes through Credential Manager and requires
a `serverClientId` (the **web** OAuth client id). It is resolved in
`google_sign_in_android-7.2.15/lib/google_sign_in_android.dart:40`:

```dart
_serverClientId = params.serverClientId ?? await _hostApi.getGoogleServicesJsonServerClientId();
```

Both sources were empty in this app:

1. `signInWithGoogle()` calls `await GoogleSignIn.instance.initialize();` with
   no `serverClientId` argument
   (`mobile/lib/features/auth/data/firebase_auth_sign_in_gateway.dart:54`), so
   `params.serverClientId` is `null`.
2. The native fallback reads the Android string resource
   `default_web_client_id`
   (`google_sign_in_android-7.2.15/android/src/main/java/io/flutter/plugins/googlesignin/GoogleSignInPlugin.java:204`).
   That resource is generated by the `com.google.gms.google-services` Gradle
   plugin from `google-services.json` — and **that plugin was never applied**.
   `mobile/android/settings.gradle.kts` declared only
   `dev.flutter.flutter-plugin-loader`, `com.android.application`, and
   `org.jetbrains.kotlin.android`; `mobile/android/app/build.gradle.kts` applied
   only `com.android.application` and `dev.flutter.flutter-gradle-plugin`.

With both `null`, the plugin fails with
`GetCredentialFailureType.missingServerClientId`, mapped to
`GoogleSignInExceptionCode.clientConfigurationError` with the description
`serverClientId must be provided on Android`
(`google_sign_in_android.dart:213-215`). `_guard` then swallows that
`GoogleSignInException` into `UnexpectedAuthFailure`, which the UI renders as
the generic "Đã có lỗi xảy ra, hãy thử lại."

`mobile/android/app/google-services.json` already contains the correct web
OAuth client (`client_type: 3`,
`591718769021-3qll01ehinlrk3aaddl6l0fk4ordipte.apps.googleusercontent.com`), and
`applicationId = "com.snapsofts.cupid"` matches its `package_name` — the file
was simply never processed, because Firebase itself is initialised from
`mobile/lib/firebase_options.dart` and so nothing else in the build depended on
the Gradle plugin being present.

This also explains "always fails": it is a build-configuration defect, not an
intermittent or account-specific one.

### Secondary defect (contributing, not fixed here)

`_guard`'s ADR-7 funnel (REQ-002 STORY-001) collapses every
`GoogleSignInException`, `SignInWithAppleException`, and `PlatformException`
into `UnexpectedAuthFailure` with no logging. That is why a fully deterministic
configuration error surfaced to the user — and to diagnosis — as an opaque
generic message, and why reproducing this required patching the app. Changing
the funnel is out of scope for this bug; see the residual note in
`fix-evidence.md`.

## Fix Scope

Apply the `com.google.gms.google-services` Gradle plugin so the already-correct,
already-committed `google-services.json` is processed and
`default_web_client_id` is generated. This is preferred over hardcoding the
client id into `initialize(serverClientId: ...)` in Dart because it keeps a
single source of truth and adds no config duplication.

Files in scope (2):
- `mobile/android/settings.gradle.kts`
- `mobile/android/app/build.gradle.kts`

No Dart source is changed.

## Residual Risk Identified During Diagnosis

`google-services.json` contains **no** `client_type: 1` (Android) OAuth client
and therefore no registered `certificate_hash`. Supplying `serverClientId`
fixes the proven root cause, but was flagged during diagnosis as possibly not
sufficient on its own. See `fix-evidence.md` — this risk materialised.

### Confirmed root-cause chain (final)

Both diagnosed causes are now closed:
- Cause 1 (repository defect, fixed by this bugfix): the
  `com.google.gms.google-services` Gradle plugin was never applied, so
  `serverClientId` was absent and Google sign-in failed before any native call.
- Cause 2 (external project configuration, fixed by the user): the debug signing
  certificate was not registered as an Android OAuth client, so Google Play
  Services rejected the credential request after account selection with
  `[16] Account reauth failed.`

With both closed, the flow completes: Credential Manager returns an ID token and
`FirebaseAuth` authenticates the user. See `fix-evidence.md` §Recheck After
Blocker Resolution for gate results and log evidence.
